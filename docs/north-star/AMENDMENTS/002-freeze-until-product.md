**Status:** accepted
**Type:** ladder
**From:** constitution v1.0 / ladder v1.1

**Evidence:** Owner: Agent OS serves TaxiLabs CI; TaxiLabs CI does not wait for Agent OS. The detour was becoming the project. Useful-enough eval: rows 1–3 are enough to import; rows 4–7 are kernel completeness.

## Why

v1 (rows 1–3) shipped. Opening 4–7 (hooks, GitHub workflow, ceremony collapse, pack dogfood) would finish *inevitability* before a product has used the pack. That inverts the rule of thumb.

Invariant 5 (minimum mechanism) already forbids adding enforcement until a demonstrated risk requires it. This amendment records the freeze so a later session cannot treat “unit 4 is next” as automatic.

## What changes

Ladder opening policy only. Unit contracts 1–7 stay. Constitution unchanged.

**Frozen:** do not open rows **4–7** until one of:

- a product that imported this kernel skips the protocol and it costs something, or
- a second product imports and the same skip risk is demonstrated.

The named product is `taxi-labs-customer-intelligence`. Learning happens there.

- **Operate:** freeze dies if the next session starts `unit/4-*` because the banner was only in chat. Mitigate: ladder + North Star + WORKING_STATE all point here.
- **Ladder:** none of 1–3 invalidated. None added, split, or renumbered. 4–7 remain named and unopened. Catalog: new operate/purpose row — opening kernel units before a product skip makes the detour the project.
